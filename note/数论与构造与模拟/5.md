# 算法错题笔记 — 位运算与环形配对题型（E 题）

此笔记总结 E 题（首尾相连数组按位异或清零）的常见错误及思考方法，帮助在类似位运算与环形问题中少踩坑。

## 题目回顾

给定首尾相连的数组 `a`（长度 `n`），一次操作选择相邻的两个元素 `a[i]` 与 `a[(i+1) mod n]`，以及一个非负整数 `k`，并令这两个元素同时异或 `2^k`。问能否把所有元素变为 0，如果可以，求最少操作次数。

## 错误集中点

* **忽略按位独立性。** 异或操作对每个二进制位独立，题目可以分解为对每一位单独处理，再将结果相加。有的代码直接对整数运算或将不同位混合处理，易出错。

* **奇偶性判定遗漏。** 一次操作翻转两个相邻元素同一位，该位上 `1` 的个数奇偶性不变。若某一位上 `1` 的个数是奇数，则无法全部清零，应直接返回 `-1`。很多实现忘记这一不变量导致得到错误答案。

* **只考虑线性配对。** 常见错误是只按 `pos[0]-pos[1], pos[2]-pos[3], …` 顺序配对 `1` 的位置。然而由于数组首尾相连，还存在另一种跨首尾配法 `pos[1]-pos[2], pos[3]-pos[4], …, pos[last]-pos[0]`，应从两种配对方式中取较小值。忽略第二种配对会导致最少操作次数计算偏大。

* **跨首尾距离计算错误。** 跨首尾相邻位置的距离是 1，而有些代码错误地计算为 `te[0] + n + 1 - te.back()`，多加了 1。例如对于 `n = 4, a = [1, 0, 0, 1]`，正确的距离是 `pos[0] + n - pos.back()` ，错误实现会得到 2。

* **使用浮点移位/位宽错误。** 题目保证 `0 ≤ a[i] < 2^30`，所以只需枚举 30 位（0～29 位）。有的解枚举了 32 位甚至使用 `1 << 31`，造成符号位溢出和未定义行为。正确做法是使用 `1LL << bit` 遍历 30 位。

* **未使用长整型。** 操作次数可能累加很多，应使用 `long long`。有错误实现使用 `int` 导致溢出或截断。

* **传值与引用混淆。** 某些代码中函数参数未使用引用导致结果不回写，例如 `void up_my(..., vector<int> v)` 将向量传值，修改不会反映回原数组。

## 正确做法思路

1. **逐位处理。** 对每个二进制位 `bit`：
   - 统计该位上 `1` 的下标 `pos[]`。
   - 若 `pos.size()` 为奇数，直接返回 `-1`。

2. **计算两种配对方案：**
   - **方案一：** 按顺序配对 `pos[0]` 与 `pos[1]`，`pos[2]` 与 `pos[3]` …，距离为相减结果。累加得到 `s1`。
   - **方案二：** 从第二个开始配对 `pos[1]` 与 `pos[2]`，依次类推，最后一个 `pos[last]` 与第一个 `pos[0]` 配对，距离为 `pos[0] + n - pos.back()`。累加得到 `s2`。
   - 该位所需操作次数为 `min(s1, s2)`。

3. **或者使用“选边法”。** 将数组视为环形图，一次操作等价于选取一条边翻转两个端点。我们用变量 `x[i]` 表示是否选择边 `(i, i+1 mod n)`。令 `b[i]` 为该位上第 `i` 个元素的 0/1 值，那么约束为 `x[i-1] ^ x[i] = b[i]`。假设 `x[n-1] = 0`，从左至右推导 `x[i]` 并统计选择的边数 `cnt`，另外一组方案就是取反选择（因为环形可以整体取反），操作次数为 `min(cnt, n - cnt)`。该方法无需显式存储 `pos` 数组，也能得出最少操作次数。

4. **累加各位贡献。** 对每位计算的最少操作次数累加即为答案。别忘了当数组初始全为 0 时输出 0。

通过以上方法，可以处理这类位运算加环形约束的题目，并有效规避常见错误。
